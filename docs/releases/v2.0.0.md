# Spec Kit 2.0 — 总 Skill 与知识包

Spec Kit 2.0 引入可选的 **Codex + `$speckit` + 知识包** 模式。
Codex 直接完成开发，总 Skill 根据实际任务选择知识和 workflow，工具负责
记录需求与澄清、执行明确的门禁、关联当前代码的验收证据。

## 新能力

- 一个正文约 50 行的原生总 Skill，详细操作按需读取。
- 8 个通用 workflow：轻量编码、工程变更、调查、只验证、交付，及知识建立、维护、发布。
- 个人、组织、项目、组件、任务层级的知识组合；支持 reference、policy、asset、workflow、skill、tool、action、check、mcp、hook。
- 包命名空间、精确依赖、固定 Git commit、内容指纹和不可变版本；安装不执行包内脚本。
- 原始需求、修订、澄清来源、workflow 选择理由、执行收据、AI 逐项验收、人工反馈与知识处置，形成可追查的任务记录。
- 源码或输入变化使旧证据失效；JSON 报告失败时，退出码 0 也不能通过；自动回答不能代替人工确认。
- 知识地图及运行调试候选生成、旧知识显式导入、来源变化提示与经人工审查的本地版本发布。
- 包安装事务、异常回滚、缺失缓存恢复和中断恢复，保护用户后续修改。

## 开始使用

新项目安装 2.0 CLI 后，在目标项目执行（已有项目先按[安装指南](../agent-setup.md)识别模式并安全升级）：

```powershell
specify init --here --mode codex-skill --no-git --json
specify pack doctor --json
specify context --json
```

重新打开该项目的 Codex 对话，再描述需求：

```text
$speckit 修复登录失败时提示不明确的问题，先核实原因，完成后给出验证结果。
```

也可以把下面一句粘贴给具备终端和文件能力的 Agent：

```text
请读取 https://raw.githubusercontent.com/liuminxin45/spec-kit/main/docs/agent-setup.md，按指南在当前项目安装 Spec Kit v2.0.0；首次安装显式使用 --mode codex-skill，已有项目保留原模式；按实际模式完成自检并给出对应任务入口。
```

上面的链接使用持续维护的安装指南，CLI 仍选择 v2.0.0 正式 tag，不从 main 安装。

详见 [新模式使用说明](../codex-skill-mode.md) 和 [安装指南](../agent-setup.md)。
Release 附件提供 wheel 和带校验和的本地安装 bundle；也可从 v2.0.0 源码安装。

## 兼容与迁移

CLI 的默认初始化模式仍为 legacy，已有项目保留原流程。
新模式需显式使用 `--mode codex-skill`，入口为 `$speckit`；legacy 入口保持
`$speckit-specify`。不自动迁移活动项目，也不把业务项目知识打包进通用模板。
旧项目先检查 `specify pack migration-plan`，在隔离目录试装和导入知识后，
再决定如何迁移项目规则。

## 验证与边界

发布检查包含完整 Python 回归、生成上下文/知识索引/上下文预算校验、版本校验、
标准 wheel 构建，以及独立安装包的实际 CLI 需求测试。缺陷修复、只读故障调查
和知识生成场景保留真实命令结果；人工验收测试使用明确标记的合成 fixture。

UI 门禁已有行为测试。本次真实浏览器点击与截图尝试遇到本地连接超时，
保持阻塞，没有作为成功的 UI E2E 验收发布。原生桌面、设备、安装器和外部服务
需要各自的实际证据。

MCP/hook 描述不等于已连接能力；初始化不会修改主机配置。消息与工具引用属于
来源记录，没有独立身份签名。源码快照只覆盖声明的文件和输入范围，运行器也
不是执行沙箱。普通交付可以停在待人工验收状态，不自动标记人工通过。
