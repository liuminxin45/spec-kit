不采用重试、增加循环上限或结果兜底。Windows 问题修复编码和输出流，不增加提示词补偿。

1. 工作流：条件校验、过滤器歧义、必填分支/循环体、默认调度配置及 switch 空白处理。

本地升级快照和回滚机制。不引入 slots、多 Agent 调度、社区扩展或 bundled 项目知识包。

## 兼容与迁移

- 条件使用布尔值、true/false 字符串或单个完整 `{{ ... }}` 表达式。原来被误判为真的
  裸表达式或拼接条件必须改写；不自动猜测用户意图。
- 过滤器与比较/逻辑运算混写的歧义表达式需分步计算。
- 循环必须显式提供 steps，switch 必须提供 cases；显式空集合仍可使用。
- setup-plan 输出 FEATURE_DIR，同时保留 SPECS_DIR 别名；新模板使用新名称。
- 保留既有默认流程和用户资产冲突保护；升级后仍需检查项目状态。

已用原始 0.10.7 源码初始化临时项目，再通过新版 CLI 完成真实升级。核心升级后报告
Codex 集成仍是 0.10.7 的 warning 是正常提示；必须继续升级集成，最终状态才是 current。
在目标项目目录执行以下步骤；遇到自定义文件冲突先审查差异，不默认使用 force：

```powershell
uv tool install specify-cli --force --from git+https://github.com/liuminxin45/spec-kit.git@v1.0.0
specify upgrade --dry-run --json
specify upgrade --json
specify integration upgrade codex --dry-run --json
specify integration upgrade codex --json
specify self check --json
```

回滚应使用升级前的项目快照恢复资产与元数据，并重新安装原 CLI 版本；只降级 CLI
不会自动还原已升级的模板。发布流程不覆盖已有同名 tag，不强推远端。

## 最终实现摘要

工作流在执行和恢复前拒绝错误默认配置、缺失控制流载荷和非完整条件；条件求值入口也
执行共享校验。过滤器支持按顺序组合，并拒绝已识别的比较/逻辑优先级歧义；switch
匹配时去除输出边缘空白，保留原始输出证据。状态文件加载直接捕获打开失败，消除预检查竞态。
Windows JSON 读取显式指定 UTF-8，文档输出只过滤布尔返回值；新输出字段保留旧别名。
计划切片和任务明确携带数据模型约束。本次属于根因修复，不改变默认阶段与人工审批边界。

部分旧配置将从“静默执行错误路径”变为明确报错，需要按上述规则迁移。这是本次 1.0.0
的主要兼容变化；未引入通用表达式执行器、自动语义纠错或新的工作流阶段。
